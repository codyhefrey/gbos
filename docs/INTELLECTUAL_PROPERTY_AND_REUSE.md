## Contributions and releases
- Public contributions require contributor rights, license compatibility, provenance, security checks and maintainer review.
- Never paste private repository code, production credentials, customer records, or internal deployment/infrastructure secrets into issues, pull requests or documentation.
- The maintainers may decline or stop future open-source publication of **new, unpublished proprietary assets**, but that decision does not cancel prior license grants.
- Public code owners and automated checks assist review; they do not prevent lawful forks or guarantee absence of secrets.

## Security reports
Use the private disclosure channel documented in SECURITY.md, not public issues. Report suspected unauthorized publication promptly so access credentials can be rotated and the exposure assessed.
